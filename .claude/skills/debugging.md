## 기본 원칙

코드를 바꾸기 전에 **원인을 먼저 파악**한다.
증상만 보고 수정하면 근본 원인이 남고 다른 곳에서 다시 터진다.

## 디버깅 순서

**1. 재현**
- 버그를 일관되게 재현하는 최소 조건 찾기
- 재현 안 되면 환경 차이(OS, 브라우저, 데이터) 확인

**2. 격리**
- 문제 범위를 좁히기 — 이진 탐색 방식으로
- 최근 변경사항 확인: `git log`, `git bisect`
- 외부 의존성 제거 후 재현되는지 확인

**3. 가설**
- "아마 X 때문일 것이다" 명시적으로 가설 세우기
- 한 번에 하나씩 검증 (여러 가지 동시에 바꾸면 원인 파악 불가)

**4. 검증**
- 가설에 맞는 증거 수집 (로그, 브레이크포인트, 값 출력)
- 가설이 틀리면 다음 가설로

## 자주 놓치는 체크포인트

- 비동기 타이밍 문제 (race condition, 순서 보장 안 됨)
- 참조 vs 값 복사 (`===` 비교 시 객체 참조 동일 여부)
- 캐시 / stale 데이터 (브라우저 캐시, React Query 캐시)
- 환경변수 누락 또는 잘못된 값
- 타입 불일치 (런타임에서 `string`인데 `number`로 가정)
- null / undefined 체크 누락

## 브라우저 디버깅

```js
// 조건부 브레이크포인트 — DevTools Sources 탭
// 특정 조건일 때만 멈춤: id === 42

// 네트워크 요청 확인
// Network 탭 → XHR/Fetch 필터 → 요청/응답 확인

// React DevTools
// Components 탭 → Props/State 실시간 확인
// Profiler 탭 → 렌더 원인 확인
```

## 로깅 전략

```ts
// 구조화된 로그 — 나중에 검색 가능하게
console.log('[Auth] token refresh', { userId, expiresAt })

// 객체 전체 출력 시 JSON.stringify 사용
console.log(JSON.stringify(obj, null, 2))
```

## 막혔을 때

1. 10분 이상 막히면 잠시 멈추고 처음부터 다시 읽기
2. 문제를 소리 내어 설명해보기 (rubber duck debugging)
3. 최소 재현 코드를 새 파일에 작성해보기
