$ARGUMENTS 현재 작업 중인 코드의 더 넓은 맥락을 파악해줘.

## 목적

낯선 코드 섹션 작업 시 전체 그림을 먼저 이해한다.
"숲을 보지 못하고 나무만 보는" 상황을 방지한다.

## 확인할 것들

### 현재 모듈의 역할
- 이 코드가 시스템에서 하는 일
- 어떤 문제를 해결하기 위해 존재하는가
- 없애면 무슨 일이 생기는가 (삭제 테스트)

### 의존성 맵
- 이 모듈이 의존하는 것 (import)
- 이 모듈에 의존하는 것 (역참조)
- 핵심 데이터 플로우

### 아키텍처 맥락
- 더 큰 시스템 내에서의 위치
- 인접한 모듈과의 관계
- 설계 의도 (ADR, 주석, 이름에서 추론)

### 변경 영향 범위
- 이 코드를 수정하면 어디가 영향받는가
- 공유 상태, 이벤트, 사이드 이펙트
- 테스트 커버리지 범위

## 출력 형식

```
## 맥락 파악: {모듈/파일명}

### 역할
{한 줄 요약}

### 의존성
- 의존: {목록}
- 피의존: {목록}

### 데이터 플로우
{입력 → 처리 → 출력}

### 변경 시 영향 범위
{수정 시 주의해야 할 부분}

### 설계 의도
{왜 이렇게 만들어졌는가}
```
