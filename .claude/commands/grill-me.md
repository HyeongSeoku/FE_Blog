$ARGUMENTS 구현을 시작하기 전에 나의 생각을 검증하기 위해 날카로운 질문을 해줘.

## 목적

개발을 시작하기 전에 정렬(alignment) 문제를 사전에 해결한다.
에이전트가 이해하지 못한 채로 만들어 버리는 것보다, 먼저 제대로 이해하는 것이 낫다.

## 방식

**한 번에 하나씩** 질문한다. 답변을 기다린 뒤 다음 질문으로 넘어간다.

질문들은 다음을 파헤쳐야 한다:
- 엣지 케이스와 경계 조건
- 성공 기준 — "완료"가 정확히 무엇을 의미하는가
- 기존 코드와의 충돌 가능성
- 이 접근법이 해결하지 못하는 것
- 더 단순한 대안이 존재하는가
- 이 변경이 영향을 주는 다른 부분

## 질문 방식

막연하게 묻지 않는다. 구체적이고 날카롭게:

```
✗ "엣지 케이스는 뭔가요?"
✓ "사용자가 이미 존재하는 이메일로 가입하려 하면 어떻게 되나요? 
   지금 그 케이스를 처리하고 있나요?"
```

충돌이 있으면 즉시 짚는다:
```
"코드베이스는 X 방식을 사용하는데, 당신이 말한 건 Y 방식입니다. 
 어느 쪽을 따라야 할까요?"
```

## 종료 조건

다음이 모두 명확해지면 질문을 멈추고 구현 계획을 제안한다:
- 성공 기준이 구체적으로 정의됨
- 주요 엣지 케이스가 처리됨
- 기존 코드베이스와의 충돌이 해소됨
- 범위가 동의됨

## 사용 예시

```
/grill-me 사용자 인증에 소셜 로그인 추가
/grill-me 결제 플로우 리팩토링
```
