$ARGUMENTS 계획이나 PRD를 독립적으로 처리 가능한 수직 슬라이스(vertical slice) 이슈로 분해해.

## 핵심 원칙

**수직 슬라이스**: 각 이슈는 스키마 → API → UI → 테스트를 포함하는 얇지만 완전한 경로여야 한다.
완료된 슬라이스는 독립적으로 데모 가능해야 한다.

## 작업 과정

### 1단계 — 컨텍스트 수집
- 현재 대화의 계획 또는 참조된 이슈 파악
- 코드베이스 탐색으로 현재 상태 이해
- 프로젝트의 도메인 용어 사용

### 2단계 — 수직 슬라이스 초안 작성
각 슬라이스가 포함:
- 스키마/데이터 레이어 변경
- API/서버 로직
- UI/클라이언트 컴포넌트
- 테스트

**선호 기준**:
- 자율(AFK) 처리 가능한 이슈 vs. 인간 판단이 필요한 이슈(HITL) 구분
- 두꺼운 이슈 적게보다 얇은 이슈 많이

### 3단계 — 검토
다음에 대해 질문:
- 적절한 세분화 정도인가?
- 이슈 간 의존성이 올바른가?
- AFK vs HITL 분류가 맞는가?

### 4단계 — 이슈 생성
의존성 순서대로 생성. 각 이슈 형식:

```markdown
## {이슈 제목}

**목표**: {한 줄 설명}

**완료 기준**:
- [ ] {체크리스트 항목}

**구현 범위**:
- 스키마: {변경 사항}
- API: {변경 사항}
- UI: {변경 사항}
- 테스트: {필요한 테스트}

**선행 이슈**: #{번호} (있는 경우)

**유형**: AFK | HITL
```

## 사용 예시

```
/to-issues 사용자 대시보드에 알림 기능 추가
/to-issues [PRD 내용 붙여넣기]
```
